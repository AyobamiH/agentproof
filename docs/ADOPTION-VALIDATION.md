# Adoption validation

The next product evidence is ten independent agent installations, not more features.

For each installation preserve raw observations separately from conclusions and record: package digest, platform and Node version, start/completion time, time to first trusted receipt, commands/API calls attempted, first blocker, assistance required, confusing terminology, trust-role comprehension, exactly-once and compensation outcomes, intent to integrate, next protected action, willingness/preferred model to pay, and the single adoption-changing repair.

Success means unfamiliar agents install without OpenClaw knowledge, complete the repository-patch lifecycle, independently verify the expected receipt, understand the five roles, and encounter no critical security or mutation ambiguity. Automated speed is engineering evidence, not human adoption evidence.

After ten installations, aggregate only evidence-backed patterns. Repair portability/docs first. Do not add another action until repeated users demand the same action and its independent verification can be specified deterministically.
